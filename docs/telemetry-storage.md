# Telemetry storage

Alembic revision `0002_telemetry` adds PostgreSQL telemetry storage after the
registry.

## Fields

| Column | Rule |
| --- | --- |
| `id` | Internal generated primary key. |
| `schema_version` | Required value `1`. |
| `device_id` | Registered device foreign key. |
| `boot_id` | Required case-sensitive string. |
| `sequence_number` | Non-negative signed 64-bit integer. |
| `measured_at` | Nullable timestamp with timezone. |
| `device_uptime_ms` | Non-negative signed 64-bit integer. |
| `gateway_received_at` | Required timestamp supplied by the gateway. |
| `backend_received_at` | Generated by PostgreSQL with `clock_timestamp()`. |
| `metric`, `unit` | `temperature`, `celsius` in v1. |
| `value` | Finite PostgreSQL `NUMERIC`; no forced scale. |
| `quality` | JSON with `reading: valid` and an approved clock value. |

Clock values are `synchronised`, `unsynchronised`, `estimated`, and `unknown`.
Storage preserves a supplied measurement time for every clock quality and never
invents one.

## Identity and duplicate handling

The unique event identity is:

```text
(device_id, boot_id, sequence_number)
```

PostgreSQL enforces it during concurrent inserts. An identical retry is reported
as `duplicate`; changed immutable content for the same identity is
`identity_conflict`. Neither case changes the original row or receipt times.
Device deletion is restricted while telemetry exists.

## Time ownership

All absolute times use `TIMESTAMP WITH TIME ZONE` and backend sessions use UTC.
Python inputs must include a timezone. `device_uptime_ms` is elapsed time and
cannot substitute for wall-clock time. Clients cannot supply
`backend_received_at`; PostgreSQL owns it.

History uses synchronised measurement time when available and gateway receipt
time otherwise. The indexes support bounded per-device scans on measurement and
backend receipt times; review query plans before production-scale use.

## Apply and recover

```sh
docker compose exec -T backend python -m alembic upgrade head
docker compose exec -T backend python -m alembic current
docker compose exec -T backend python -m alembic check
```

Run migrations before enabling writers. Downgrading to `0001_registry` removes
all telemetry while preserving the registry. Stop writers and back up PostgreSQL
before testing a downgrade. Reapplying the migration creates an empty table; it
does not recover readings.

Verification commands are in [backend/README.md](../backend/README.md#run-the-checks).
